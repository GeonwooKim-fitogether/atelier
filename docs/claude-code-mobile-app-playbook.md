# Claude Code로 스마트폰 앱 만들기 — 홈페이지 제작 10단계를 앱 제작용으로 옮긴 절차

> 한 줄 요지: **챗GPT 코덱스로 홈페이지를 만드는 10단계는 순서를 그대로 두고, 도구 이름과 결과물의 종류만 바꾸면 Claude Code로 스마트폰 앱을 만드는 절차가 된다.** 설명서 파일은 `AGENTS.md`가 아니라 `CLAUDE.md`이고, 결과물은 웹사이트가 아니라 Expo(엑스포, 코드 하나로 iPhone과 Android 앱을 함께 만드는 도구)로 만든 앱이며, 확인은 브라우저가 아니라 내 손의 스마트폰에서 한다. 바뀌는 것이 정확히 무엇인지가 이 문서의 내용이다.

이 문서는 "코덱스 홈페이지 만들기 10단계" 글을 출발점으로 삼는다. 그 글의 핵심 통찰 세 가지는 앱을 만들 때도 그대로 유효하다. 첫째, 레퍼런스를 모으지 않으면 누가 만들어도 똑같은 결과물이 나온다. 둘째, 설명서 파일에 "네가 할 수 있는 일은 네가 하라"를 적어야 AI가 사람에게 일을 떠넘기지 않는다. 셋째, 무엇을 시키느냐보다 **무엇을 막느냐**가 결과를 지킨다. 아래 10단계는 이 세 가지를 지키면서 앱에 맞게 바꾼 것이다.

---

## 0. 무엇이 같고 무엇이 달라지나 — 한 장 대응표

| 단계 | 코덱스 + 홈페이지에서는 | Claude Code + 스마트폰 앱에서는 | 바뀌는 정도 |
|---|---|---|---|
| 1 초기 설정 | 추론 강도를 중간으로, 속도는 기본값 | 모델을 Sonnet 계열로, 빠른 모드(`/fast`)는 끄고, 권한 모드를 "편집 자동 승인"으로 | 이름만 다름 |
| 2 프로젝트 만들기 | 코덱스 안에서 폴더 생성 | 터미널에서 Expo 프로젝트를 만들고 그 폴더에서 `claude` 실행. 스마트폰에 Expo Go 앱 설치 | **크게 다름** |
| 3 레퍼런스 수집 | 웹플로우·핀터레스트·세이비·어워즈 | Mobbin·Dribbble·핀터레스트·경쟁 앱의 스토어 스크린샷 | 출처만 다름 |
| 4 설명서 파일 | `AGENTS.md` | `CLAUDE.md` (세션 시작 때 자동으로 읽힘) | 이름과 내용의 규격 부분이 다름 |
| 5 스킬 설치 + 생성 | `gpt-taste` 스킬 | `.claude/skills/` 폴더의 스킬. 웹용 스킬을 그대로 쓰지 않고 앱용 스킬을 하나 만든다 | **크게 다름** |
| 6 색감·폰트 | 겟디자인 파일을 `DESIGN.md`로 | 같음. 단, 폰트를 앱에 싣는 방식이 다르다 | 거의 같음 |
| 7 이미지 넣기 | `public/assets` | `assets/images` + 앱 아이콘과 시작 화면 | 거의 같음 |
| 8 움직임 넣기 | 21st.dev 부품 | 21st.dev는 웹 전용이라 직접 못 쓴다. Reanimated(리애니메이티드, React Native의 표준 애니메이션 라이브러리)로 번역시킨다 | **크게 다름** |
| 9 세이브 파일 | 코덱스의 저장 기능 | git 커밋 + Claude Code의 `/rewind` | 이름만 다름 |
| 10 배포 | "사이트" 스킬로 인터넷에 올림 | 세 단계로 나뉜다. 내 폰(Expo Go), 지인 폰(내부 배포), 스토어(EAS Build와 심사) | **크게 다름** |

"크게 다름"으로 표시된 2·5·8·10단계는 아래 본문에서 특히 자세히 다룬다. 나머지는 코덱스 글의 프롬프트에서 단어 몇 개만 바꾸면 된다.

## 1단계. Claude Code 초기 설정 (사용량 절약)

**결론: Claude Pro(월 20달러)로 시작하고, 모델은 Sonnet 계열을 기본으로 두고, 빠른 모드는 켜지 않는다.** 코덱스에서 "추론 강도를 중간으로 내리라"는 조언에 해당하는 것이 이 세 가지다.

### 1-1. 설치와 실행

Claude Code는 터미널(명령어를 글자로 입력하는 검은 창)에서 돈다. 여기서 "터미널"이 무엇인지 운영체제별로 정확히 적어 둔다.

| 운영체제 | 터미널 여는 법 | 비고 |
|---|---|---|
| Mac | Spotlight(화면 위 돋보기)에서 "터미널" 검색 | iPhone 시뮬레이터를 쓸 수 있는 유일한 운영체제다 |
| Windows | 시작 메뉴에서 "PowerShell" 검색 | iPhone 시뮬레이터가 없다. Android 에뮬레이터나 실제 폰으로 확인한다 |

설치 명령은 한 줄이다. Node.js(자바스크립트 실행기)가 먼저 설치돼 있어야 하며, Expo도 같은 것을 필요로 하므로 한 번 설치로 둘 다 해결된다.

```bash
npm install -g @anthropic-ai/claude-code
```

앱 프로젝트 폴더로 들어가 `claude`를 입력하면 시작된다. 터미널이 낯설면 VS Code 확장이나 데스크톱 앱으로도 같은 기능을 쓸 수 있다. 다만 **claude.ai 웹사이트에서 도는 원격 세션은 시뮬레이터를 띄울 수 없으므로**, 앱 제작은 내 컴퓨터에 설치한 Claude Code로 한다.

### 1-2. 사용량을 지키는 설정 세 가지

1. **모델.** Claude Code 안에서 `/model`을 입력하면 모델을 고를 수 있다. 화면을 짜고 버그를 고치는 일상 작업은 Sonnet 계열로 충분하다. 앱 전체 구조를 처음 설계할 때만 Opus로 바꾼다. 모델 선택 화면에 추론 강도(노력 수준) 항목이 보이면 기본값이 "높음"일 때 "중간"으로 내린다. 코덱스와 같은 원리다.
2. **빠른 모드.** `/fast`로 켜고 끄는 빠른 모드는 응답이 빨라지는 대신 사용량이 훨씬 많이 나간다. 켜지 않는다.
3. **대화 정리.** 한 기능이 끝나면 `/clear`로 대화를 비운다. 이전 대화가 길게 남아 있으면 매 요청마다 그 전체를 다시 읽어 사용량이 누적된다. 남은 사용량은 `/usage`로 확인한다.

### 1-3. 권한 모드 — 매번 "허용할까요?"를 누르지 않으려면

Claude Code는 기본값에서 파일을 고칠 때마다 허용을 묻는다. 혼자 만드는 앱 프로젝트에서는 `Shift+Tab`을 한 번 눌러 **"편집 자동 승인(accept edits)"** 모드로 바꾼다. 파일 편집은 묻지 않고, 명령 실행만 묻는다. `Shift+Tab`을 한 번 더 누르면 **계획 모드(plan mode)** 가 되는데, 이 모드에서는 코드를 고치지 않고 계획만 세운다. 큰 변경 전에 이 모드로 계획을 먼저 받아 보면 되돌리는 일이 줄어든다.

## 2단계. 프로젝트 만들기

**결론: Expo로 만든다.** 코덱스 글에서 "폴더 이름을 정하면 끝"이었던 단계가, 앱에서는 "어떤 기술로 만들 것인가"라는 선택을 포함하게 된다. 선택지를 하나로 정해 두는 것이 이 단계의 핵심이다.

### 2-1. 왜 Expo인가

Expo는 React Native(리액트 네이티브, 자바스크립트로 iPhone과 Android 앱을 함께 만드는 기술) 위에 얹힌 도구 모음이다. 처음 앱을 만드는 사람에게 Expo를 권하는 이유는 세 가지다.

1. **코드 하나로 두 플랫폼.** iPhone용과 Android용을 따로 만들지 않는다.
2. **폰에서 바로 본다.** 스마트폰에 Expo Go라는 앱을 설치하고 QR 코드를 찍으면, 컴퓨터에서 고친 내용이 몇 초 안에 내 폰 화면에 나타난다. Xcode나 Android Studio 같은 무거운 개발 도구를 설치하지 않아도 된다.
3. **AI가 가장 잘 아는 기술이다.** 웹사이트를 만들 때 Next.js가 그러했듯, Expo는 학습 자료가 가장 많아 Claude가 실수를 적게 한다.

Flutter(플러터, 구글의 앱 제작 도구)도 좋은 선택지이지만, 웹사이트 만들기 글의 흐름(React 계열, 21st.dev 같은 부품 생태계)을 그대로 잇기에는 Expo가 맞다.

### 2-2. 만드는 순서

1. **스마트폰에 Expo Go를 설치한다.** App Store 또는 Play 스토어에서 "Expo Go"를 검색한다. 무료다.
2. **터미널에서 프로젝트를 만든다.** 아래 한 줄이면 탭 화면과 TypeScript(타입스크립트, 오타를 미리 잡아 주는 자바스크립트)가 갖춰진 기본 앱이 생긴다. `my-app` 자리에 원하는 폴더 이름을 넣는다.

   ```bash
   npx create-expo-app@latest my-app
   cd my-app
   claude
   ```

3. **Claude Code에게 첫 실행을 시킨다.** 아래 프롬프트를 그대로 입력한다.

   > 이 Expo 프로젝트의 개발 서버를 실행해 줘. 터미널에 나오는 QR 코드를 내가 폰의 Expo Go로 찍을 수 있게 유지하고, 웹 미리보기도 함께 열어서 기본 화면이 뜨는지 스크린샷으로 확인한 뒤 결과를 보고해.

4. **폰으로 QR 코드를 찍는다.** 컴퓨터와 폰이 같은 Wi-Fi에 있어야 한다. iPhone은 기본 카메라 앱으로, Android는 Expo Go 앱 안의 스캔 버튼으로 찍는다. 기본 앱 화면이 폰에 뜨면 이 단계는 끝이다.

### 2-3. 코덱스의 "사이트 스킬 쓰지 마라"에 해당하는 금지 두 가지

코덱스 글에서 "디자인할 때 사이트 스킬을 쓰면 밋밋하게 나온다"고 경고했듯, 앱에도 처음부터 막아야 할 것이 있다. 이 두 가지는 4단계에서 `CLAUDE.md`의 금지 목록에 넣는다.

- **웹 전용 라이브러리를 쓰지 않는다.** Tailwind CSS(웹용 스타일 도구), framer-motion(웹용 애니메이션), shadcn/ui(웹용 부품 모음)는 웹사이트용이라 앱에서 돌지 않거나 겉모습만 흉내 낸다. Claude가 웹 습관대로 이것들을 끌어오면 앱이 깨진다.
- **네이티브 코드로 빠져나가지 않는다.** `npx expo prebuild`라는 명령은 Expo의 보호 울타리를 벗어나 iOS와 Android 원본 코드를 직접 만든다. 배포 직전까지는 이 울타리 안에 머무는 것이 초보자에게 훨씬 안전하다.

## 3단계. 레퍼런스 앱 수집하기

**결론: 이 단계가 결과물의 차이를 결정한다는 점은 웹과 똑같다.** "그냥 앱 만들어 줘"라고 하면 회색 카드가 나열된, 어디서나 본 앱이 나온다. 앱 화면을 모아 둔 곳은 웹사이트와 다르므로 출처만 바꾼다.

| 출처 | 무엇을 보나 | 검색어 예 |
|---|---|---|
| Mobbin (mobbin.com) | 실제 출시된 앱의 화면 흐름을 앱별·패턴별로 모아 둔 곳. 온보딩, 탭 구성, 설정 화면 같은 **패턴**을 보기에 가장 좋다 | 앱 이름 또는 "onboarding", "paywall" |
| Dribbble (dribbble.com) | 디자이너들의 시안. 색감과 분위기를 보기에 좋다 | "mobile app ui", "habit tracker app" |
| 핀터레스트 | Dribbble과 비슷하되 더 넓다 | "앱 UI 디자인", "mobile onboarding" |
| 경쟁 앱의 스토어 페이지 | App Store와 Play 스토어의 앱 소개 화면에는 그 앱의 대표 화면 대여섯 장이 실려 있다. 실제로 팔리는 앱의 화면이라는 점이 시안과 다르다 | 내가 만들 앱의 경쟁 앱 이름 |

코덱스 글과 같은 방식으로 **두 개만 고른다.** 첫 번째에서 전체 분위기와 글자 크기를, 두 번째에서 화면 구성 방식(탭이 몇 개인지, 목록이 카드인지 줄인지)을 가져온다.

캡처한 이미지는 프로젝트 폴더 안에 `refs/ref1`, `refs/ref2` 폴더로 나눠 저장한다. Claude Code는 이미지 파일을 직접 열어 볼 수 있으므로, 프롬프트에 폴더 경로만 적으면 된다. 터미널에 이미지를 붙여 넣는 방법도 있지만, 폴더에 두면 다음 세션에서도 다시 쓸 수 있어 폴더 방식을 권한다.

## 4단계. 설명서 파일(`CLAUDE.md`) 만들기

**결론: 코덱스의 `AGENTS.md`에 해당하는 파일이 `CLAUDE.md`다.** Claude Code는 세션을 시작할 때마다 프로젝트 최상위의 이 파일을 자동으로 읽으므로, 여기에 적은 규칙은 매번 다시 말하지 않아도 지켜진다. 코덱스 글의 프롬프트에서 웹 규격("가로 1920px, 컨테이너 1280px")을 앱 규격으로 바꾸는 것이 핵심이다.

### 4-1. 첫 프롬프트 — 대괄호 안만 내 것으로 바꾼다

아래는 예시로 "하루 물 마시기 기록 앱"을 넣은 것이다. 대괄호 안을 내 앱 내용으로 바꿔 그대로 입력한다.

> 아래 내용을 바탕으로 프로젝트 최상위 폴더에 CLAUDE.md라는 설명서 파일을 만들어 줘.
>
> [기술] Expo 최신 SDK + TypeScript + Expo Router(파일 이름이 곧 화면 주소가 되는 화면 이동 방식)로 스마트폰 앱을 만든다. iPhone과 Android 둘 다 대상이다.
>
> [목적] 하루 물 섭취량을 기록하고 목표 달성을 도와주는 개인용 습관 앱이다.
>
> [누가 쓰는 앱인가]
> - 건강 관리를 시작한 20~40대 직장인
> - 하루에 앱을 여는 횟수는 5~8회, 한 번에 10초 안에 기록을 끝내고 싶어 한다
> - 알림을 받고 들어오는 경우가 절반이다
>
> [이 앱을 켠 사람이 해야 할 행동] 앱을 열고 3초 안에 "한 잔 추가" 버튼을 누르게 만드는 것이 목표다. 그 다음 목표는 주간 기록 화면에서 연속 달성 일수를 확인하게 하는 것이다.
>
> [화면 구성]
> 1) 온보딩 3장 — 목표량 설정과 알림 허용
> 2) 홈 탭 — 오늘 마신 양, 목표 대비 진행률, 한 잔 추가 버튼
> 3) 기록 탭 — 주간·월간 달성 그래프
> 4) 설정 탭 — 목표량, 알림 시각, 단위
> 5) 기록 상세 — 하루의 기록 목록과 수정
>
> [전체 규격]
> - 기준 화면은 논리 픽셀 390×844(iPhone 15 크기)이고, 360×640(보급형 Android)에서도 깨지지 않아야 한다
> - 세이프 에어리어(노치와 홈 인디케이터가 차지하는 위아래 영역)를 반드시 비운다
> - 터치할 수 있는 요소는 최소 44×44 포인트
> - 세로 모드만 지원한다
> - 라이트 모드와 다크 모드 모두 지원한다
> - 화면 하나에 주요 행동 버튼은 하나만 둔다
>
> [금지]
> - 이모지를 아이콘 대신 쓰지 않는다
> - 웹 전용 라이브러리(Tailwind CSS, framer-motion, shadcn/ui)를 쓰지 않는다
> - `npx expo prebuild`로 네이티브 코드를 생성하지 않는다
> - 같은 크기의 카드를 격자로 반복 배치하는 것을 기본 레이아웃으로 삼지 않는다
> - 목록의 모든 항목을 회색 테두리 카드로 감싸지 않는다

전송하면 설명서 파일이 만들어진다. 코덱스와 마찬가지로 접근성과 성능 원칙, 금지 사항 체크리스트를 알아서 채운다.

### 4-2. 두 번째 프롬프트 — "네가 할 수 있는 일은 네가 하라"

코덱스 글의 "진짜 꿀팁"에 해당하는 부분이다. 앱에서는 이 규칙이 웹보다 더 중요하다. **Claude는 내 폰 화면을 볼 수 없기 때문에**, 스스로 확인할 수 있는 통로(웹 미리보기나 시뮬레이터의 스크린샷)를 명시해 주지 않으면 "폰에서 확인해 보세요"라고 사람에게 떠넘긴다.

> 아래 내용을 CLAUDE.md 맨 상단에 추가해 줘.
>
> 네가 스스로 할 수 있는 일은 나에게 시키지 말고 스스로 실행해라. 개발 서버 실행, 타입 검사(`npx tsc --noEmit`), 화면 확인까지 직접 하고 결과만 보고해라.
>
> 화면 확인은 다음 순서로 한다. 첫째, 웹 미리보기(`npx expo start --web`)를 열어 390×844와 360×640 두 크기로 스크린샷을 찍는다. 둘째, iPhone 시뮬레이터나 Android 에뮬레이터가 있으면 거기서도 스크린샷을 찍는다. 셋째, 두 크기에서 글자가 잘리거나 버튼이 겹치는 곳이 없는지 스크린샷을 직접 보고 판단한다. 스크린샷을 찍지 않은 화면은 "확인했다"고 말하지 않는다.
>
> 아이콘은 Phosphor Icons의 React Native 판(`phosphor-react-native`)을 사용한다. 애니메이션은 `react-native-reanimated`, 이미지는 `expo-image`, 터치 진동은 `expo-haptics`를 사용한다.
>
> 디자인 작업에는 웹용 스킬(design-taste-frontend 등)을 쓰지 않고 mobile-taste 스킬만 쓴다.

마지막 줄의 `mobile-taste`는 5단계에서 만든다.

### 4-3. 이 프로젝트(Atelier)와의 연결

이 저장소에서 기획한 앱을 만들 때는 대괄호 안을 새로 쓰지 않는다. `idea/<이름>/06-service-design.md`(서비스 설계)와 `09-handoff.md`(인계 문서)에 이미 목적·사용자·화면 구성이 정리돼 있으므로, 그 내용을 대괄호 자리에 옮기면 된다. 기획 단계의 산출물이 곧 설명서 파일의 재료가 되는 것이 이 연결의 뜻이다.

실제로 채운 예가 하나 있다. 묵주기도 앱(mobile-rosary)의 V1을 위 서식으로 채운 프롬프트가 [`idea/mobile-rosary/claude-md-prompt.md`](../idea/mobile-rosary/claude-md-prompt.md)에 있다. 다른 앱을 채울 때 그 파일을 본보기로 삼는다.

## 5단계. 앱용 스킬 만들기 + 앱 생성

**결론: 웹용 `gpt-taste` 스킬을 그대로 쓰지 않고, 앱용 스킬 `mobile-taste`를 하나 만든다.** 스킬은 코덱스에서와 같은 뜻이다. AI가 작업 전에 먼저 읽는 지침서이고, Claude Code에서는 `.claude/skills/<이름>/SKILL.md` 파일이 스킬이며 `/이름`으로 부른다.

### 5-1. 왜 웹용 스킬을 그대로 쓰면 안 되나

`gpt-taste`와 이 저장소에 이미 있는 `design-taste-frontend` 스킬은 첫 줄에 "랜딩 페이지, 포트폴리오, 리디자인용. 여러 단계로 된 제품 UI용이 아니다"라고 스스로 밝히고 있다. 히어로 섹션, 스크롤 애니메이션, 1280px 컨테이너 같은 웹의 어휘로 쓰여 있어, 앱에 적용하면 "스크롤하는 웹페이지를 폰 크기로 줄인 것"이 나온다. 앱은 탭·시트·제스처·상태(로딩·비어 있음·오류)라는 다른 어휘를 가진다.

### 5-2. 설치 방법 두 가지

**방법 A — 코덱스 글과 같은 명령으로 설치.** 스킬 설치 명령은 Claude Code에서도 똑같이 동작한다. 어느 도구에 설치할지 물으면 Claude Code를 고른다. 앤트로픽이 공개한 범용 UI 스킬 `frontend-design`을 설치하는 예다.

> 아래 명령어를 실행해서 frontend-design 스킬을 설치해 줘.
> `npx skills add anthropics/skills --skill frontend-design`

**방법 B — 앱 전용 스킬을 직접 만든다(권장).** Claude Code에게 아래 프롬프트를 주면 `.claude/skills/mobile-taste/SKILL.md`를 만든다. 스킬의 알맹이는 "무엇을 기본값으로 삼지 말 것인가"의 목록이다.

> `.claude/skills/mobile-taste/SKILL.md` 파일을 만들어 줘. 이 스킬은 스마트폰 앱 화면을 만들 때 먼저 읽는 디자인 지침서다. 다음 내용을 담아라.
>
> 1. 작업 전에 한 줄로 "이 앱을 무엇으로 읽었는가"를 선언한다. 누가 쓰는 어떤 종류의 앱이고, 어떤 분위기이며, iOS와 Android 어느 관례를 따를지를 한 문장으로 적는다.
> 2. AI가 기본값으로 내놓는 앱 모양을 금지한다. 보라색 그라데이션, 모든 항목을 같은 회색 카드로 감싸기, 아이콘만 다섯 개 나열한 하단 탭, 화면마다 큰 제목과 부제를 반복하기, Inter 폰트, 이모지 아이콘.
> 3. 간격은 4포인트 단위로만 쓴다. 글자 크기 단계는 5개 이내로 정하고 그 밖의 크기를 쓰지 않는다.
> 4. 모든 목록 화면은 세 가지 상태(불러오는 중, 비어 있음, 오류)를 반드시 설계한다. 비어 있는 화면에는 다음 행동을 안내하는 문장과 버튼을 둔다.
> 5. 터치 대상은 최소 44×44 포인트, 세이프 에어리어를 존중하고, 주요 행동 버튼은 엄지가 닿는 화면 아래쪽에 둔다.
> 6. 애니메이션은 화면 전환과 상태 변화에만 쓰고 장식용 무한 반복 애니메이션은 쓰지 않는다.
> 7. 코드를 쓰기 전에 위 항목을 점검한 체크리스트를 먼저 출력한다.

스킬을 설치하거나 만든 뒤에는 **Claude Code를 한 번 종료하고 다시 실행**해야 적용된다. 작업한 내용은 사라지지 않는다. 다시 켜서 `/`를 입력하면 목록에 `mobile-taste`가 보여야 한다.

### 5-3. 앱 생성 프롬프트

코덱스 글의 생성 프롬프트에서 스킬 이름과 폴더 이름만 바뀐다. "그대로 복제하지 말고"라는 문장이 핵심이라는 점도 같다.

> /mobile-taste 프로젝트 안 refs/ref1, refs/ref2 폴더의 참고 이미지들의 분위기와 화면 구성 방향을 참고해서, CLAUDE.md에 정리된 앱을 만들어 줘.
> - ref1 폴더: 전체 분위기와 글자 크기 기준
> - ref2 폴더: 탭 구성과 목록 배치 기준, 색감과 여백 기준
> 이미지를 그대로 복제하지 말고 구조와 분위기만 참고해.
> 작업이 끝나면 CLAUDE.md의 작업 규칙에 따라 웹 미리보기 두 크기와 시뮬레이터에서 스크린샷으로 점검한 뒤, 폰의 Expo Go에서 내가 볼 수 있게 개발 서버를 켜 둔 상태로 결과를 보고해.

결과가 나오면 폰의 Expo Go를 새로 고쳐 실제 화면을 본다. 이 확인은 사람만 할 수 있는 몫이다.

## 6단계. 색감·폰트 바꾸기

**결론: 코덱스 글과 거의 같다.** 겟디자인(getdesign.dev)에서 받은 디자인 기준 파일을 `DESIGN.md`로 저장하고 다시 입히는 절차는 그대로다. 앱에서 한 가지 다른 점은 **폰트 파일을 앱 안에 실어야 한다**는 것이다. 웹은 폰트를 인터넷에서 불러오지만, 앱은 설치 파일에 폰트를 포함시킨다.

프롬프트는 이렇게 바뀐다.

> 첨부한 파일 내용을 프로젝트 루트에 DESIGN.md로 만들어서 저장하고, 그 디자인 시스템에 맞게 앱 전체를 다시 입혀 줘. 색상·글자 크기·간격 값은 `constants/theme.ts` 한 파일에 토큰으로 모으고, 모든 화면은 그 파일만 참조하게 해.
> 폰트는 expo-font로 앱에 싣는다. 구글 폰트에 있는 폰트는 `@expo-google-fonts` 패키지로, 없는 폰트(예: Pretendard)는 ttf 파일을 `assets/fonts`에 넣어 불러온다.
> 반드시 지킬 것
> - 화면 구성, 탭 순서, 레이아웃 배치는 절대 바꾸지 마라
> - 애니메이션과 인터랙션도 그대로 유지해라
> - 바꾸는 것은 색상, 폰트, 간격, 질감뿐이다
> 작업 후 두 크기 스크린샷으로 직접 확인하고 결과를 보고해라.

코덱스 글의 경고도 그대로 유효하다. **"바꾸지 마라"를 안 적으면 앱을 처음부터 다시 만들어 버릴 수 있다.** 한국어 앱이면 Pretendard처럼 한글 자형이 정리된 폰트를 고르는 것이 낫다. 구글 폰트에 있는 한글 폰트로는 Noto Sans KR, IBM Plex Sans KR이 있다.

## 7단계. 내 이미지 넣기 + 앱 아이콘

**결론: 이미지 폴더는 `assets/images`이고, 웹에는 없던 두 가지 이미지가 추가된다.** 앱 아이콘과 시작 화면(스플래시)이다. 이 둘이 기본값 그대로면 폰 홈 화면에서 "만들다 만 앱"처럼 보인다.

첫 프롬프트는 코덱스 글과 같다.

> 앞으로 생성하는 이미지와 내가 직접 넣는 이미지는 전부 `assets/images` 폴더에 저장할 거야. 이 규칙을 CLAUDE.md에도 추가해라.

이미지를 폴더에 넣은 뒤의 프롬프트다.

> `assets/images` 폴더에 실제 이미지를 넣어 뒀어. 홈 화면의 그림 자리와 온보딩 세 장에 순서대로 넣고, 비율이 안 맞는 건 잘리지 않게(`expo-image`의 `contentFit="contain"`) 처리해 줘.
> 그리고 `assets/images/icon.png`(1024×1024)와 `splash-icon.png`를 앱 아이콘과 시작 화면으로 `app.json`에 연결해 줘. 아이콘 이미지는 내가 넣어 뒀어.

아이콘 이미지가 아직 없으면 Claude에게 "DESIGN.md의 색으로 단순한 아이콘을 SVG로 그려서 PNG로 변환해 넣어 달라"고 하면 임시 아이콘을 만든다. 스토어에 올릴 때는 정식 아이콘으로 바꾼다.

## 8단계. 움직임 넣기

**결론: 21st.dev의 부품은 웹(React + Tailwind) 전용이라 앱에 그대로 넣을 수 없다.** 대신 두 가지 길이 있다. 앱용 부품 출처에서 가져오거나, 21st.dev의 프롬프트에서 **의도만** 가져와 Reanimated로 번역시킨다.

### 8-1. 앱용 움직임 부품 출처

| 출처 | 무엇인가 |
|---|---|
| React Native Reanimated 공식 예제 (docs.swmansion.com/react-native-reanimated) | React Native 애니메이션의 표준 라이브러리. 예제 페이지에 카드 넘기기, 늘어나는 헤더, 바텀 시트 같은 앱에서 자주 쓰는 움직임이 있다 |
| Moti (moti.fyi) | Reanimated를 짧은 코드로 쓰게 해 주는 도구. 웹의 framer-motion과 쓰는 느낌이 비슷하다 |
| react-native-reusables | 웹의 shadcn/ui를 앱용으로 옮긴 부품 모음. 버튼, 시트, 토스트 같은 기본 부품 |

### 8-2. 21st.dev 부품을 번역시키는 프롬프트

21st.dev에서 마음에 드는 것을 골라 화면을 캡처하고, 캡처 이미지를 `refs/motion` 폴더에 넣은 뒤 이렇게 요청한다. "글로만 설명하면 다르게 이해할 수 있으니 화면도 함께 넣으라"는 코덱스 글의 조언은 여기서 더 중요하다. 번역이 들어가기 때문이다.

> [21st.dev에서 복사한 프롬프트 붙여넣기]
> 위 컴포넌트는 웹용이야. `refs/motion` 폴더의 캡처 이미지를 보고 같은 움직임을 `react-native-reanimated`로 다시 구현해서, 기록 탭의 주간 그래프 카드에만 적용해 줘.
> 반드시 지킬 것
> - 지금 색상, 폰트, 레이아웃은 그대로 두고 움직임만 가져올 것
> - 다른 화면은 건드리지 말 것
> - 웹 라이브러리를 설치하지 말 것
> - 버튼을 누를 때 `expo-haptics`로 짧은 진동을 함께 줄 것
> - 스킬은 사용하지 말 것

마지막의 진동 한 줄은 웹에는 없는, 앱만이 가진 촉각 피드백이다. 이 한 줄이 "웹페이지를 폰에 넣은 것"과 "앱"의 체감 차이를 크게 만든다.

## 9단계. 세이브 파일 만들기

**결론: 코덱스 글의 세 프롬프트가 그대로 통한다.** Claude Code는 저장에 git(파일의 변경 이력을 남기는 도구)을 쓰는데, 자연어로 말하면 알아서 git 명령을 실행한다. 여기에 Claude Code만의 되돌리기 장치가 하나 더 있다.

| 하고 싶은 것 | 프롬프트 | 뒤에서 일어나는 일 |
|---|---|---|
| 저장하기 | "지금까지 작업한 상태를 저장해 줘. 이름도 알아서 붙여 줘." | git 커밋이 만들어진다 |
| 목록 확인 | "지금까지 저장된 목록을 전부 보여 줘." | `git log`를 읽어 시각과 이름을 보여 준다 |
| 되돌리기 | "[저장 이름] 시점으로 되돌려 줘." | 그 커밋 상태로 파일을 복원한다 |

**Claude Code만의 추가 장치, `/rewind`.** 대화 중 `Esc`를 두 번 누르거나 `/rewind`를 입력하면, 이번 세션 안에서 Claude가 파일을 고친 시점들이 목록으로 나오고 그중 하나로 코드를 되돌릴 수 있다. 저장하라고 말하지 않았어도 자동으로 기록돼 있다는 점이 편리하다. 다만 이것은 **이번 세션 안에서만** 유효하므로, 하루 작업이 끝날 때는 위 표의 "저장하기"를 꼭 한 번 한다.

컴퓨터가 고장 나도 안전하게 두고 싶으면 "GitHub에 이 프로젝트를 올려 줘"라고 하면 된다. GitHub 계정 로그인은 사람이 한 번 해야 한다.

## 10단계. 배포하기 — 웹과 가장 크게 다른 단계

**결론: 웹은 "인터넷에 올리면 끝"이지만, 앱은 누구에게 보여 주느냐에 따라 세 단계로 나뉘고, 단계마다 드는 비용과 시간이 다르다.** 코덱스 글의 "사이트 스킬" 같은 한 방 도구는 없다. 대신 Expo가 제공하는 EAS(Expo Application Services, Expo의 빌드·배포 서비스)를 쓴다.

| 단계 | 누가 보나 | 방법 | 비용 | 걸리는 시간 |
|---|---|---|---|---|
| ① 내 폰 | 나 | Expo Go에서 QR 스캔 (2단계에서 이미 하고 있다) | 무료 | 즉시 |
| ② 지인 폰 | 5~20명 | **Android:** EAS Build로 APK 파일을 만들어 링크로 보낸다. 받는 사람은 링크를 눌러 설치한다. **iPhone:** 애플 개발자 계정이 있어야 하고, TestFlight(애플의 시험판 배포 앱)로 초대한다 | Android 무료, iPhone은 애플 개발자 계정 연 99달러 | Android 30분, iPhone 하루 |
| ③ 스토어 | 누구나 | EAS Build로 스토어용 파일을 만들고 EAS Submit으로 제출한다. 심사를 통과하면 게시된다 | 애플 연 99달러, 구글 1회 25달러 | 심사 1~7일 |

**빠르게 "보여 주기"만 하려면 웹으로 내보내는 길도 있다.** Expo 앱은 웹으로도 빌드되므로 `npx expo export --platform web`으로 만든 결과물을 Vercel 같은 곳에 올리면 링크 하나로 브라우저에서 볼 수 있다. 진동이나 알림처럼 폰에서만 되는 기능은 빠지지만, 화면과 흐름을 보여 주기에는 충분하다.

### 10-1. 지인에게 Android로 보여 주는 프롬프트 (가장 쉬운 ②)

> EAS Build로 Android 내부 배포용 APK를 만들어 줘. `eas.json`에 preview 프로필을 만들고, 빌드가 끝나면 설치 링크를 알려 줘. 로그인이 필요하면 어느 화면에서 무엇을 눌러야 하는지 알려 주고 멈춰.

### 10-2. 사람이 해야 하는 몫

배포에서 Claude가 대신 못 하는 것은 계정과 결제다. Claude가 아래 부탁을 하면, 각각 브라우저에서 하면 된다.

- **Expo 계정 만들기와 로그인.** expo.dev에서 무료 가입한다. Claude가 `eas login`을 실행하면 터미널에 아이디와 비밀번호를 입력하는 것은 사람이 한다.
- **애플 개발자 계정 (iPhone에 배포할 때만).** developer.apple.com에서 가입하고 연 99달러를 결제한다. 승인에 하루 이틀 걸리므로 배포 일정보다 먼저 한다.
- **구글 플레이 개발자 계정 (스토어 출시 때만).** play.google.com/console에서 1회 25달러를 결제한다.

### 10-3. 코덱스의 "나만 보기를 인터넷의 누구나로 바꿔라"에 해당하는 것

TestFlight와 Play 스토어의 내부 테스트는 **초대한 사람만** 볼 수 있다. 지인이 "링크가 안 열린다"고 하면 열 중 아홉은 초대 목록에 그 사람의 이메일이 없어서다. 초대는 App Store Connect(애플)나 Play Console(구글) 웹사이트에서 사람이 한다.

## 11. Claude Code에서만 할 수 있는 튜닝 — 코덱스에는 없던 것

위 10단계는 코덱스 글의 대응이다. 여기부터는 Claude Code가 추가로 가진 손잡이인데, **앱 하나를 처음 만드는 사람은 아래 첫 두 개만 알아도 충분하다.** 나머지는 두 번째 앱부터 쓴다.

### 11-1. 설명서를 두 층으로 나눈다 (권장)

`CLAUDE.md`는 두 곳에 둘 수 있다. 프로젝트 폴더의 것은 **이 앱**의 규칙이고, 내 홈 폴더 `~/.claude/CLAUDE.md`의 것은 **내가 만드는 모든 프로젝트**에 적용되는 규칙이다. "네가 할 수 있는 일은 네가 하라", "한국어로 보고하라", "보고 끝에 확인 방법 세 줄(어디서, 무엇을 하면, 무엇이 보이나)을 적으라"처럼 앱과 무관한 내 취향은 홈 폴더 쪽에 한 번만 적어 두면 다음 프로젝트에서 다시 쓰지 않아도 된다.

### 11-2. 자동 검사를 훅으로 건다 (권장)

훅(hook)은 "Claude가 어떤 일을 할 때마다 자동으로 실행되는 명령"이다. 파일을 고칠 때마다 타입 검사를 자동으로 돌리게 하면, Claude가 "완료했다"고 말하기 전에 오류를 스스로 보게 된다. 설정은 Claude Code에게 말로 시키면 된다.

> 파일을 편집한 직후마다 `npx tsc --noEmit`을 자동으로 실행해서 타입 오류가 있으면 나에게 알려 주는 훅을 `.claude/settings.json`에 추가해 줘. 그리고 `npx expo`, `npm`, `npx tsc` 명령은 매번 묻지 말고 허용 목록에 넣어 줘.

두 번째 문장은 1단계의 권한 모드를 보완한다. 편집 자동 승인 모드에서도 명령 실행은 묻는데, 자주 쓰는 명령을 허용 목록에 넣으면 그 질문도 사라진다.

### 11-3. 계획 모드로 큰 변경을 먼저 검토한다

새 탭을 추가하거나 데이터 저장 방식을 바꾸는 것처럼 여러 파일에 걸치는 변경은 `Shift+Tab` 두 번으로 계획 모드에 들어가 "어떻게 할 건지 계획만 세워 줘"라고 먼저 묻는다. 계획을 읽고 마음에 들면 승인해 실행시킨다. 코드가 한 줄도 바뀌지 않은 상태에서 방향을 고칠 수 있으므로, 9단계의 되돌리기를 쓸 일이 줄어든다.

### 11-4. 시뮬레이터를 Claude가 직접 조작하게 한다 (고급, 선택)

Mac에서 iPhone 시뮬레이터를 쓰거나 Android 에뮬레이터를 쓴다면, MCP(Model Context Protocol, Claude에 외부 도구를 연결하는 규격) 서버 중 시뮬레이터를 조작하는 것(예: mobile-mcp)을 연결할 수 있다. 연결하면 Claude가 스스로 앱을 탭하고 스크롤하고 스크린샷을 찍어 확인한다. 4-2의 "화면 확인" 규칙이 웹 미리보기를 넘어 실제 앱 화면까지 미치게 된다. 설치와 설정이 따로 필요하므로 첫 앱에서는 건너뛰어도 된다.

## 12. 한 장 요약 — 무엇을 만들든 순서는 같다

코덱스 글의 마지막 문장은 앱에도 그대로 적용된다. 포트폴리오 대신 습관 앱을 예로 들었지만, 가계부·명상·독서 기록 앱도 똑같다. 바뀌는 것은 4단계 설명서 파일에 무엇을 적느냐뿐이다.

1. Claude Code를 설치하고 모델과 권한 모드를 정한다.
2. Expo 프로젝트를 만들고 폰의 Expo Go에서 기본 화면을 본다.
3. 앱 레퍼런스를 두 개 모아 `refs` 폴더에 넣는다.
4. `CLAUDE.md`에 목적·사용자·화면·규격·금지를 적고, "네가 할 수 있는 일은 네가 하라"를 맨 위에 붙인다.
5. 앱용 스킬 `mobile-taste`를 만들고 앱을 생성한다.
6. `DESIGN.md`로 색과 폰트를 입힌다.
7. 이미지와 앱 아이콘을 넣는다.
8. 움직임을 Reanimated로 번역해 넣는다.
9. 저장하고, 필요하면 되돌린다.
10. 내 폰에서, 지인 폰에서, 스토어에서 순서대로 배포한다.

이 문서에 적힌 프롬프트는 전부 그대로 복사해 쓸 수 있게 만들었다. 대괄호와 예시(물 마시기 앱) 부분만 내 앱으로 바꾼다.
