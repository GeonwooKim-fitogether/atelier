## 2. 07-a spec 의 형식

파일 자리는 `idea/<slug>/07-prototype/a-wireframe.spec.json`이다. 생성물(`a-wireframe.html`)은 **손으로 고치지 않는다.** spec을 고치고 다시 생성한다.

```json
{
  "title": "화면 설계도 제목",
  "eyebrow": "<slug> V1 · 07-a 산출물",
  "lead": ["머리말 문단", "..."],

  "flowSvg": "a-flow.svg",
  "flowCaption": "도해 설명",

  "screens": [
    {
      "name": "홈 · 상태 A",
      "sheet": false,
      "desc": "이 화면이 무엇인지 한 단락. 책 5-2 가 요구하는 설명이다",
      "elements": [
        { "label": "요소 이름", "flex": 19, "style": "solid", "bars": ["w50"], "prov": true },
        { "grow": true },
        { "flex": 12, "row": [ { "label": "왼쪽" }, { "label": "오른쪽", "style": "dashed" } ] }
      ]
    }
  ],

  "xref": [ { "us": "US-01", "cond": "Given ...", "screen": "화면 3" } ],
  "xrefNote": "지목되지 않은 조건에 대한 설명 (생략하면 자동 문장이 들어간다)",

  "findings": [
    { "tag": "발견 1 · 화면 4", "title": "무엇이 안 정해졌나", "body": "왜 문제인가", "prov": "잠정으로 무엇을 정했나" }
  ],

  "verdict": [ { "cond": "조건", "state": "상태" } ],
  "footer": "맺음말"
}
```

### 요소(element)의 값

| 열쇠 | 뜻 |
|---|---|
| `label` | 상자 안에 들어갈 설명. 실제 문구가 아니라 **무엇이 놓이는지**를 적는다 |
| `flex` | 화면 높이에서 차지하는 비율(%). 생략하면 내용만큼 |
| `style` | `solid`(그 화면의 주요 행동) · `dashed`(조건부로만 나타남, 또는 약한 위계) · `plain`(테두리 없음) · 생략(보통 상자) |
| `bars` | 글줄을 흉내 내는 막대. `w95` `w80` `w65` `w50` `w35` `w22`, 앞에 `t`를 붙이면 얇은 줄 (`tw35`) |
| `prov` | `true`면 **잠정** 표시가 붙는다. 06이 정하지 않아 임의로 그린 자리 |
| `grow` | 빈 공간. `{ "grow": true }` |
| `row` | 가로로 나란히 놓을 요소들 |

`"sheet": true`를 주면 그 화면이 **아래에서 올라오는 시트**로 그려진다. 흐린 배경과 손잡이가 자동으로 붙으므로 `grow` 스페이서를 따로 넣지 않는다.

### 본문에 쓸 수 있는 표시

`lead` · `desc` · `body` · `prov` · `xrefNote` · `footer`에서는 `**굵게**`와 `` `코드` `` 두 가지만 쓸 수 있다. 나머지는 글자 그대로 나온다.

## 3. 07-a 가 지켜야 할 두 금지

엔진이 구조로 강제하는 것과 사람이 지켜야 하는 것을 갈라 둔다.

| 금지 | 누가 막나 |
|---|---|
| 색을 쓰지 않는다 (회색 단계만) | **엔진이 막는다.** 템플릿에 무채색 토큰만 있다. 게이트 G7A-6이 생성물을 다시 잰다 |
| 07-a에서 정한 요소 위치를 07-b에서 바꾸지 않는다 | 사람이 지킨다. 바꾸려면 spec을 고치고 07-a를 다시 생성한다 |
