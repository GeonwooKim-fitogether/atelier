# 묶음 4 장치 — 06 서비스 설계 · 07 시제품 · 08 검증

> 한 줄 요지: **이 폴더는 묶음 4가 사람의 기억에 기대지 않게 만드는 장치 모음이다.** 게이트는 단계에 들어가기 전에 앞 단계 산출물이 실제로 있는지 기계가 재고, 엔진은 07-a를 매번 같은 모양으로 뽑는다.

지휘 절차는 `../SKILL.md`의 묶음 4 절이 정하고, 07단계의 실행 서식은 저장소의 [`docs/stage-07-procedure.md`](../../../../docs/stage-07-procedure.md)가 정본이다. 이 폴더는 그 둘이 말로 정한 것 중 **기계가 할 수 있는 부분**을 맡는다.

## 왜 만들었나

2026-09-05에 mobile-rosary 07-b가 교착에 빠졌다. 07-b의 통과 조건이 "06의 디자인 시스템을 실제로 적용했다"인데 06 산출물에 그 절이 아예 없었다. 적용할 대상이 없으니 통과도 반려도 판정할 수 없었고, 만드는 쪽은 매번 자기 기본값으로 그려 매번 반려됐다.

이 결함의 성질이 이 폴더의 존재 이유다. **아무도 오류를 내지 않는다.** 06 문서는 멀쩡해 보이고, 07은 시작할 수 있는 것처럼 보이며, 결함은 만든 뒤 사람이 볼 때에야 드러난다. 사람의 기억으로 막는 방식은 같은 자리에서 이미 세 번 실패했다.

## 무엇이 들어 있나

| 파일 | 무엇을 하나 | 사람이 하는 일 |
|---|---|---|
| `gate.mjs` | 06·07-a·07-b·07-c·07-d·08 여섯 관문을 파일 검사로 판정하고, 통과하지 못한 첫 자리를 "다음 한 걸음"으로 지목한다 | 결과를 읽는다 |

| `schema.md` | spec JSON의 서식과 06 산출물이 갖춰야 할 절 | 읽는다 |

## 쓰는 법

```bash

node .claude/skills/atelier-npi/bundle4/gate.mjs <idea-slug>

# 07-a 를 spec 에서 생성한다
node .claude/skills/atelier-npi/bundle4/wireframe.mjs <idea-slug>

# 대시보드나 다른 장치가 소비할 형태로
node .claude/skills/atelier-npi/bundle4/gate.mjs <idea-slug> --json
```

`--strict`를 붙이면 미통과 관문이 있을 때 종료 코드 1을 낸다. 자동 검사에 걸 때 쓴다.

## 이 장치들이 하지 않는 것

정직하게 적어 둔다. **내용의 좋고 나쁨은 판정하지 않는다.** 재는 것은 "있는가, 이어져 있는가"뿐이다.

- 목업이 아름다운가 — 사람(공방장)이 본다. 게이트는 `○` 표시로 남긴다.
- 받는 사이가 호흡에 맞는가 — 사람이 실제로 겪어 본다.
- 와이어프레임의 배치가 옳은가 — 사람이 본다.
- 유저 플로 도해 — 엔진이 그리지 않는다. 분기가 있는 흐름의 자동 배치는 손으로 놓는 것보다 나은 결과를 내기 어렵다. spec의 `flowSvg`가 가리키는 파일을 끼워 넣고, 없으면 **없다는 사실을 화면에 남긴다.**

기계가 잡는 것은 **빠짐**이다. 빠짐은 조용하고, 판단은 조용하지 않다.

## 왜 이 폴더에 있나

원본 우선 규칙상 `.claude/commands/`와 `.claude/workflows/`는 창고(Template-repository)가 원본이라, 여기서 새로 만들면 동기화 봇이 덮어쓰거나 두 곳이 영구히 갈라진다. 반면 `.claude/skills/atelier-npi/`는 저장소 README가 **이 저장소 고유**로 못 박아 두었다. 그래서 Atelier 전용 장치는 이 스킬 폴더 안에 둔다.
