> 박제된 결정. 코드(D-NNN)는 대시보드 엔진이 읽는 식별자이고, 서술의 정본은 루트 [`../decisions.md`](../decisions.md)·[`../charter.md`](../charter.md)·[`../idea-funnel.md`](../idea-funnel.md)다.

### D-009 — Stage 2B 완료 · 프로토타입을 클릭으로 실측 검증

MyRosary 프로토타입과 목업 4장을 만들고, 제작 에이전트가 조직 사용 한도로 중단된 뒤 남은 시각 검증 루프를 이어받아 완료했다. F1(이어서 바치기)·F2(내 페이스)의 수용 기준이 실제 클릭으로 재현되는 것을 확인했고, 이어서 카드의 인라인 span 레이아웃 붕괴 결함 하나를 고쳤다. 관련: WP-003.

### D-008 — CEO 부재 3시간 자율 진행 · 판정은 잠정+추인 대기로 남긴다

charter §4.2(v0.3)가 허용하는 모드. 조작은 진행하되 Pass/Hold/Kill/Freeze 는 사람 전속이므로, 판정이 필요한 지점은 멈추지 않고 잠정안과 "추인 대기" 꼬리표로 기록했다. 그 목록이 decision-queue.md 의 DQ-001~006 이다.

### D-007 — 정본 대조 규칙: "따른다"는 정본을 전부 읽은 뒤에만 쓴다

대시보드를 만들면서 정본 패턴 파일을 첫 몇 줄만 훑고 "그 패턴을 따른다"고 적은 사고에서 나온 규칙. 읽지 않았으면 "정본 미대조 — 임의 설계"라고 그대로 적는다. 금지되는 것은 임의 설계가 아니라 대조 없이 대조했다고 쓰는 것이다.

### D-006 — 판단의 표면은 대시보드다

최종 결정(Stage 판정·도구 확정·순서)은 Agent 의 채팅 서술이 아니라 대시보드를 보고 내린다(대표 지시). 판단 근거가 대화 스크롤에 흩어지면 결정의 재현·회고가 불가능하기 때문이다. 이 결정의 집행이 `progress-dashboard` 엔진 렌더다.

### D-005 — MyRosary Stage 1 Pass

이동 중 기도의 통증(실물 휴대 불편·기존 앱 사용성·발견성)이 1인칭 경험과 외부 흔적에서 확인됐다. wedge 는 "내 페이스로 · 진행이 기억되고 · 준비가 필요 없는 이동 중 기도". Depth 는 기간형이므로 Kill Signal 도 기간형이어야 한다. 관련: WP-002.

### D-004 — 첫 실사이클 안건은 MyRosary, 사내 시스템 Stage 2 는 대기

진짜 외부 사용자 안건으로 방법론을 먼저 검증해 자기참조 위험을 없애고, 두 사이클 경험 위에서 시스템 PRD 를 쓴다. 이 결정이 funnel 최초의 "Stage 2 대기" 실데이터를 만들었다. 관련: WP-004.

### D-003 — 사내 상품기획 시스템 Stage 1 Pass

주 단위로 발생하는 일상 기획 판단이 받는 구조 없이 흩어진다는 통증. 97일 공백은 대표 확인(원인 = 우선순위)으로 통증 증거에서 기각했다. 관련: WP-004.

### D-002 — charter v0.3 ACCEPT (PR #1 머지)

단계적 개방(§1.4 — 공방 → 사내 시스템 → SaaS)과 척추(§3.4 — 단계는 근거 딸린 판정으로만, freeze 된 PRD 는 불변)를 신설하고 충돌 조항 6개를 개정했다. 창고 동기화 봇 첫 실행이 성공해 공용 규칙 4종·훅이 내려왔다. 관련: WP-001.

### D-001 — 진행 계획 승인 — Phase 1까지

6개 국면 중 Phase 1(첫 실사이클)까지만 승인. Phase 2(Foundry 인계)는 Foundry→창고 이관 완료 후 재설계한다. 관련: WP-001.

### D-010 — 대시보드는 손으로 짜지 않는다 · `progress-dashboard` 엔진이 정본이다

손으로 만든 `dashboard.html` 두 판을 폐기하고, 창고 공용 스킬 `progress-dashboard`(Director Dashboard 엔진)로 렌더한다. 엔진은 "직접 HTML 을 짜지 말고 config + data 를 채워 돌려라"를 스킬 설명에 명시하고 있었는데 두 번 무시했다. 엔진이 읽는 정본 소스를 실제로 만들었다 — `meta/decisions.md`(D-NNN) · `meta/decision-queue.md`(DQ-NNN) · `ai-npi/WP-*_Worklist.md`(T-NNN) · `dashboard.config.json`(레인·워크패키지·행위자). 산출물은 `.claude/progress-dashboard.html`.

행위자(actors)는 스킬 절차상 첫 실행 전에 물어야 하는데, 대표 부재·긴급 상황이라 잠정으로 공방장(대표)/Atelier Agent/System 셋을 넣고 렌더했다. **행위자 구성은 추인 대상이다.**
