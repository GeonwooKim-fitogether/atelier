# 레퍼런스 — mobile-rosary 07-b 목업의 시각 기준

> 한 줄 요지: **공방장이 2026-09-05에 33장을 골라 넣었다.** 성화 17장은 앱 안에 실릴 그림의 톤을 정하고, 화면 캡처 16장은 화면 자체의 분위기와 배치를 정한다. 이 폴더가 채워지면서 [`../00-brief.md`](../00-brief.md)의 `[레퍼런스]` 빈 칸이 닫혔다.

레퍼런스가 왜 사람이 골라야 하는지는 [`docs/stage-07-procedure.md`](../../../../docs/stage-07-procedure.md) §5에 있다. 요지는 AI가 고르면 그것이 다시 AI의 취향이 되기 때문이다.

---

## 1. 폴더가 각각 무엇의 기준인가

| 폴더 | 장수 | 무엇의 기준인가 |
|---|---|---|
| `01-sacred-images/` | 17 | **앱 안에 실릴 그림의 톤.** 어떤 성화가 이 앱에 어울리는지를 정한다. 화면의 바탕색·글꼴을 정하는 기준은 아니다 |
| `02-captures/webflow/` | 10 | **화면의 분위기와 배치.** 여기에 세 사이트가 섞여 있고 서로 방향이 다르다 (아래 §3) |
| `02-captures/awwwards/` | 4 | 극단적 대비와 큰 글씨의 예. 흑백 위주 |
| `02-captures/savee/` | 2 | 글자 자체를 재료로 쓰는 예. 본문 조판과 글자 겹치기 |

`02-captures` 안의 16장 중 **8장이 실제 휴대폰 폭(약 460×910)** 으로 잡혀 있다 — `webflow/04·05·06`(Ovelle Holm)과 `webflow/07·08·09·10`(Focused), 그리고 `webflow/01`(Liore). 나머지는 데스크톱 화면이다. 휴대폰 폭 캡처가 목업에 훨씬 직접 쓰인다.

## 2. 파일 이름을 손댄 곳

원본 다섯 장의 이름이 이 환경에서 읽을 수 없는 상태(`다운로드 (13)` 계열이 깨져 있었다)여서, **그림을 보고 내용으로 이름을 다시 붙였다.** 그림 자체는 손대지 않았다.

| 새 이름 | 무엇이 그려져 있나 |
|---|---|
| `13_Mosaic_Jesus_Water.jpg` | 물 위를 걷는 예수, 파스텔 모자이크 |
| `14_Swirl_Jesus_Arms.jpg` | 팔 벌린 예수, 청색·황금 소용돌이 (반 고흐풍) |
| `15_Pastel_Crowd.jpg` | 흰 옷의 군중, 파스텔 임파스토 |
| `16_Dove_Clouds.jpg` | 구름 사이 비둘기, 사진에 가까운 표현 |
| `17_Oil_Mary_Tomb.jpg` | 무덤가의 성모, 고전 유화 |

영문 이름이 길고 공백이 있던 두 장도 짧게 바꿨다(`11_Mary_Rosary_White_Gold.jpg`, `12_Mary_Child_Neutral.jpg`). 나머지 열 장은 원본 이름 그대로다.

## 3. 실제로 읽은 것 — 색을 값으로 뽑았다

눈으로만 읽지 않고 각 묶음의 지배색을 실제로 추출했다(그림을 160px로 줄여 중간값 분할로 양자화한 뒤 묶음 전체에서 점유율 순으로 집계). 아래 값은 그 결과다.

### 성화 17장 — 따뜻한 백색과 낮은 채도

| 색 | 점유 | 성격 |
|---|---|---|
| `#d0d0c0` `#c0c0b0` | 각 3~4% | 아주 낮은 채도의 상아색 (색상 60도, 채도 11~15) |
| `#d0c0a0` `#b0a080` | 각 4% | 금빛 계열 (색상 40도, **채도 23~34**) |
| `#e0d0c0` `#c0b0a0` | 각 4% | 따뜻한 크림 (색상 30도) |
| `#f0f0f0` `#e0e0e0` | 각 3% | 거의 흰색 |
| `#304050` | 3% | 유일한 어두운 색. 10·14·17번(청색 성모·소용돌이·유화)에서 나온다 |

**열일곱 장 중 열두 장이 같은 가족이다** — 두껍게 칠한 물감이나 석고 부조의 질감에, 따뜻한 백색 바탕과 금빛 광원. 나머지 다섯 장(9 스테인드글라스풍·10 청색 성모·13 모자이크·14 소용돌이·15 파스텔 군중)은 채도가 확 높아 이 가족에서 떨어져 있다.

여기서 중요한 값 하나: **금빛의 채도가 34 이하로 낮다.** 같은 색상(40도)이지만 채도 71인 형광 금색은 이 묶음에 없다. 이 차이가 뒤에서 갈림길이 된다.

### 화면 캡처 — 세 방향이 섞여 있고 서로 반대다

| 묶음 | 지배색 | 성격 |
|---|---|---|
| **Ovelle Holm** (`webflow/03~06`) | `#f0f0f0` **55%** · `#f0f0e0`(따뜻한 오프화이트) 7% · 잉크 `#303030` | 밝은 종이 바탕. 갤러리 전시 안내 |
| **Focused** (`webflow/07~10`) | `#000000` **46%** · 금색 `#c09020`(채도 71) · 청색 `#103070` | 검은 바탕에 형광 금색·청색. 사진 스튜디오 |
| **INFINI · Matthew Fisher** (`awwwards/*`) | `#f0f0f0` 43% + `#000000` 15% | 무채색 극단 대비. 큰 글씨 |

## 4. Ovelle Holm을 자세히 본 이유

휴대폰 폭 캡처 넷 중 이 묶음이 이 앱에 가장 가깝다. `webflow/04_Ovelle_Holm_Info.png`를 원본 크기로 보면 조판 규칙이 그대로 읽힌다.

| 요소 | 어떻게 쓰였나 | 이 앱의 어디에 대응하나 |
|---|---|---|
| 제목 | 대비가 큰 세리프(명조 계열), 두 줄로 크게. "After the Long Quiet" | 단과 신비 이름 |
| 작은 라벨 | 대문자, 자간을 넓게 벌린 아주 작은 글씨, 회색. "MEDIUM" "WORKS ON VIEW" "CURATOR" | 알 번호 표시 ("알 4 / 10") |
| 값 | 라벨 바로 아래, 보통 크기 | 기도문 본문 |
| 배치 | 라벨과 값을 두 칸으로 나란히, 사이에 머리카락처럼 얇은 선 | 기도 화면의 정보 띠 |
| 단추 | 테두리만 있는 알약 모양, 두 줄 글씨. "Book a viewing" | 시작 단추 |
| 강조 방법 | 굵기가 아니라 **크기와 여백**으로 위계를 만든다 | 화면 하나에 주요 행동 하나 원칙과 맞는다 |
| 색이 있는 판 | 따뜻한 오프화이트 판을 한 군데만 깔아 목록을 묶는다 | 이어가기 카드 |

우연이지만 짚어 둘 만한 것이 있다. 이 사이트의 문구가 **"After the Long Quiet"** 와 **"Quiet rooms, loud work."** 다. 고요를 다루는 어휘를 이미 쓰고 있어서, 기도 앱의 톤과 겹친다.

## 5. 이 레퍼런스가 06의 가설과 어긋나는 곳 하나

**`03-analysis.md` §5는 "다크 모드 기본(잠자기 전 환경)"을 UX 톤 가설로 적어 두었고, `07-prototype/v1`은 거의 검은 바탕(`#0b0b0d`)으로 만들어져 있다.** 그런데 이번 레퍼런스는 반대쪽을 가리킨다.

- 성화 열일곱 장 중 열두 장이 따뜻한 백색 계열이다.
- 화면 캡처에서 휴대폰 폭으로 잡힌 넷 중 Ovelle Holm 셋이 밝은 종이 바탕이다.
- 어두운 방향의 레퍼런스는 Focused 넷인데, 그 넷은 형광 금색과 청색을 쓰는 사진 스튜디오 사이트여서 성화 묶음의 낮은 채도와 맞지 않는다.

**이 어긋남은 이 문서가 판정하지 않는다.** 06의 디자인 토큰을 정할 때 공방장이 판정할 자리이며, 판정에 필요한 사실은 §3의 값과 아래 §6의 사용 맥락이다.

## 6. 판정에 함께 놓아야 하는 사용 맥락

`01-intake.md`가 적은 사용 자리는 **잠자기 전 침대**와 **퇴근길 대중교통**이고, 둘 다 어두운 환경이다. 밝은 화면은 그 자리에서 세 가지 마찰을 만든다. 눈이 부시고, 잠들기 어려워지고, 옆 사람에게 화면이 보인다. 세 번째는 01단계가 적은 마찰 4번("화면이 남에게 보이는 게 신경 쓰임")과 정확히 같은 항목이다.

그래서 이 어긋남은 취향 대결이 아니라 **"어디에 밝은 톤을 쓰고 어디에 어두운 톤을 쓰나"** 의 문제로 읽힌다. 가능한 답 셋을 사실만 적어 둔다.

| 답 | 무엇을 뜻하나 | 무엇을 잃나 |
|---|---|---|
| **가.** 화면은 어둡게, 그림과 강조색만 성화의 따뜻한 백색·금빛에서 가져온다 | 사용 맥락을 지키면서 레퍼런스의 톤을 강조색과 이미지로 살린다 | Ovelle Holm의 밝은 종이 인상은 포기한다 |
| **나.** 화면을 밝게(따뜻한 오프화이트), 어두운 환경을 위해 밝기를 낮추는 장치를 따로 둔다 | 레퍼런스를 가장 곧게 따른다 | 잠자기 전 눈부심과 화면 노출 문제가 남는다. 장치를 하나 더 만들어야 한다 |
| **다.** 두 모드를 다 만들고 기본을 어둡게 둔다 | 브리프의 "다크 모드가 기본이고 라이트 모드도 지원한다"와 맞는다 | 목업을 두 벌 만들어야 해서 07-b의 작업량이 늘어난다 |

## 7. 아직 없는 레퍼런스 하나

절차 문서 §5가 권한 것 중 하나가 빠져 있다 — **지금 쓰는 Marcello 앱의 화면 캡처**다. 이 앱의 1등 가치가 단순함이고 우리가 그것을 깨지 않기로 했으므로(`00-brief.md` `[금지]` 첫 줄), **단순함의 기준선이 그림으로 있으면 목업이 그 선을 넘었는지 판정할 수 있다.** 없어도 07-b를 시작할 수는 있으니 막는 항목은 아니다.

앱 화면 패턴을 모아 둔 곳(Mobbin)의 캡처도 없다. 이번 캡처는 웹사이트 위주여서 분위기와 조판에는 쓰이지만, 앱 고유의 구조(시트가 올라오는 방식, 하단 단추 배치)에는 기준을 주지 않는다.
