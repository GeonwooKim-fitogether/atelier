# 화면 명세 (06-d) — mobile-rosary V1

> 서식 정본: [`docs/prototype-vocabulary.md` §7-2](../../docs/prototype-vocabulary.md). 이 문서가 그 서식의 **첫 실행**이다.
> 입력: [`06-prd.md`](./06-prd.md)의 FR-## · [`06-design-system.md`](./06-design-system.md) · [`06-service-design.md`](./06-service-design.md)의 정보 구조.

**이 문서의 성격을 정직하게 적는다.** v2 통합 시제품이 이 명세보다 먼저 만들어졌다(2026-08-29). 그때 즉석에서 내려진 화면 결정들을 여기서 **기록된 설계로 확정**하고, 즉석 결정이 놓친 것을 명세 과정에서 잡는다. 다음 안건부터는 이 문서가 목업보다 먼저 온다. 명세와 v2가 다른 곳은 **[v2 어긋남]** 으로 표시했다 — 이것이 07-b 개정의 작업 목록이 된다.

화면은 셋, 시트는 셋이다: 홈 · 기도 · 완주 / 지향 추가 · 받는 사이 · 소개.

## 화면 1 — 홈

**목적 한 줄**: "지금 바로 시작(또는 재개)할 수 있는가"에 3초 안에 답한다.

**진입·이탈**: 앱 실행 시 유일한 진입점. 이탈은 기도 화면(시작·이어가기)뿐. 뒤로 가기 = 앱 종료(iOS 관행).

**요소 표**

| 요소 | 상태 | 각 상태에서 | FR |
|---|---|---|---|
| 오늘의 신비 | 4종 (요일 자동) | 신비 이름을 세리프로. 조작 불가 — 정보다 | FR-01 |
| 음성 없음 안내 | 숨김(기본) / 표시 | 한국어 음성 부재 시에만. 촛불색, 붉은색 금지 | 오류표 |
| 이어가기 카드 | **없음(기본)** / 있음 | 위치("제N단 M번째 알")와 시각("방금·N분 전·어제"). 탭 = 그 자리에서 재개 | FR-02·03 |
| 지향 카드 | 선택됨 / 아님 × 진행 있음 / 없음 | 탭 = 활성 지향 교체, 이어가기 카드가 그 지향 것으로 바뀜 | FR-04 |
| 지향 추가 | 기본 | 탭 = 지향 추가 시트 | FR-05 |
| 시작 단추 | 진행 없음("시작") / 있음("처음부터 다시") | 탭 = 저장 자리 삭제 후 처음부터 | FR-18·02 |
| 침묵 진행 토글 | 꺼짐 / 켜짐 | 상태 유지. 켤 때 진동 3연타로 예고 | FR-06 |
| 받는 사이 | 라벨(느리게/보통/빠르게) | 탭 = 속도 시트 | FR-07 |

**문구 표**

| 자리 | 확정 문구 |
|---|---|
| 이어가기 카드 머리 | `이어서 바치기` |
| 이어가기 본문 | `제{N}단 {M}번째 알 부터 이어서` **[v2 어긋남 — "알 부터"는 붙여 쓴다: "알부터"]** |
| 진행 없는 지향 | `아직 시작하지 않음` |
| 하단 안내 | `앞 절은 앱이, 뒷 절은 직접 바칩니다.` / `중간에 끊겨도 그 자리가 남습니다.` |
| 음성 없음 | `이 기기에 한국어 음성이 없어 소리 없이 진행됩니다. 진동과 받는 사이는 그대로 동작합니다.` |

**빈·오류 상태**: 첫 실행 = 지향 1개("오늘의 지향")·진행 없음·이어가기 카드 없음. 이것이 기본 모습이므로 "비어 보이는" 상태가 곧 정상 상태다. 저장 실패 시 안내 1회(오류표).

**명세 밖 (일부러 없음)**: 통계·연속 기록·달력, 알림 설정, 계정. 오늘 날짜 표시(신비가 요일을 이미 담는다).

## 화면 2 — 기도

**목적 한 줄**: "지금 내 차례인가, 어디쯤인가"를 화면을 응시하지 않고도 알린다.

**진입·이탈**: 홈에서만 진입. 이탈 셋 — 잠시 멈춤(자리 저장→홈) / 여기서 끝내기(자리 삭제→홈) / 완주(→완주 화면). 앱 이탈(전화·홈 버튼) = 자동으로 자리 저장 후 정지(FR-17, 오류표).

**요소 표**

| 요소 | 상태 | 각 상태에서 | FR |
|---|---|---|---|
| **가운데 알 (시그니처)** | 읽는 중 / 내 차례 / 침묵 / 단 전환 | 읽는 중 = 테두리가 앞 절 길이에 맞춰 차오름 · 내 차례 = 4초 호흡 · 단 전환 = 확장 맥동 | FR-15 |
| 알 속 숫자 | 성모송 중 / 그 외 | `N / 10` (시작 기도는 `/ 3`) · 그 외는 `·` | FR-16 |
| 5단 막대 | 지남 / 지금 / 남음 | 보라 계열, 조작 불가 | FR-16 |
| 단계 이름·지향 | 항상 | 상단 한 줄씩. 지향은 말줄임 | — |
| 기도문 앞 절 | 읽는 중 강조 | 세리프 `prayer-lg` | FR-11 |
| 기도문 뒷 절 | 대기(회) / 내 차례(촛불색) | 색 전환 0.5s | FR-11 |
| 잠시 멈춤 | 기본 | 부제 `자리가 남습니다` | FR-18 |
| 여기서 끝내기 | 기본 | 부제 `처음부터 다시` | FR-18 |

**비화면 채널 명세 (§7-3) — 이 화면의 절반은 소리와 진동이다**

| 채널 | 규칙 |
|---|---|
| 음성 | 앞 절만 읽는다(FR-11). 속도 0.92 (기본보다 느리게 — 기도의 호흡). 뒷 절·신비 선포 뒤 해설은 읽지 않는다 |
| 받는 사이 | `(900ms + 뒷절 글자수 × 132ms) ÷ 속도계수(0.75/1/1.35)`. 무음이면 `앞절 글자수 × 118ms` 가산. 신비 선포는 고정 2200ms | 
| 진동 사전 | 알 넘어감 `18ms` 1회 · 단 전환 `28-60-28-60-28` · 침묵 켬 `20-50-20` · **완주 [v2 어긋남 — v2에 없음. 길게 한 번(200ms) 추가: 눈 감은 사용자가 끝을 알아야 한다]** |
| 무음·무진동 기기 | 사이만으로 진행. 오류 없음 |

**문구 표**: 이 화면에 조작 문구는 위 버튼 둘뿐. **"받아 바치세요" 같은 지시문을 두지 않는다** — 알의 호흡이 그 역할이다(디자인 시스템 §4). [v2 정합 ✓]

**빈·오류 상태**: 해당 없음(홈을 거쳐야만 진입).

**명세 밖**: 배속, 건너뛰기 단추(기도는 탐색하는 것이 아니다), 화면 내 텍스트 스크롤(사도신경도 한 화면에 — 글자 크기가 줄더라도 `clamp` 하한 유지).

## 이 명세가 잡아낸 것 — 즉석 설계와의 차이 3건

명세를 쓰는 행위 자체가 검사였다. v2를 만들 때 즉석에서 지나간 것 셋이 걸렸다.

1. **완주 진동이 없다.** 눈 감은 사용자(주 맥락!)는 끝난 것을 모른다. 진동 사전에 추가 — 07-b 개정 목록 1번.
2. **"알 부터" 띄어쓰기** — 조사 오류.
3. **명세 밖 목록이 없었다.** "넣자는 제안이 반복될 것"(공유 카드·연속 기록·배속)을 명시적으로 거절해 두지 않으면 다음 세션이 선의로 넣는다.

**07-b 개정 목록**: 위 1·2번. (3번은 이 문서 자체가 해결.)
