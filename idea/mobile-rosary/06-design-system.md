# 디자인 시스템 — mobile-rosary V1

> 한 줄 요지: **이 앱의 화면이 하는 일은 "보게 만드는 것"이 아니라 "안 봐도 되게 만드는 것"이다.** 그래서 모든 결정이 한 방향을 향한다 — 곁눈질로도 읽히고, 어두운 곳에서 눈을 찌르지 않고, 끊겨도 벌주지 않는다.

이 문서는 06단계(서비스 설계)의 산출물이다. 화면을 그리기 **전에** 정해져야 하는 것들이며, 07-b 목업의 수용 기준이 된다. 어휘와 단계 정의는 [`docs/prototype-vocabulary.md`](../../docs/prototype-vocabulary.md)를 따른다.

**기준선 (2026-08-28 공방장 확정): 경쟁자를 이기는 선 — Marcello보다 세련.** Marcello의 1등 가치인 단순함은 지키되, 완성도는 Calm·Headspace 수준을 목표로 한다. 03단계 포지셔닝이 "단순·세련 UX"를 우리 자리로 정했으므로 이것은 취향이 아니라 **사업 가설**이다.

## 1. 어디서 가져왔나 — 이 제품의 세계

일반적인 다크 모드를 쓰지 않는다. 색과 형태를 **묵주기도라는 세계 안에서** 가져온다.

| 이 제품의 물건 | 디자인으로 옮긴 것 |
|---|---|
| 밤의 성당 — 완전한 검정이 아니라 보랏빛이 도는 어둠 | 바탕색에 보라를 아주 조금 섞는다 (`#0C0A11`) |
| 촛불 — 흔들리는 따뜻한 빛 | 주 강조색을 촛농색으로 (`#E8D6A8`). 파랑·청록을 쓰지 않는다 |
| 전례색 보라 — 대림·사순의 색이자 성모의 색 | 부 강조색 (`#9C8CC9`) |
| 제대포(祭臺布) — 흰 아마천 | 본문 글자색 (`#F2EEE6`). 순백이 아니라 천의 흰색 |
| **묵주 알** | **화면의 주인공.** 아래 §4 참조 |

## 2. 색 토큰

```css
--night:   #0C0A11;   /* 바탕 — 밤의 성당. 보랏빛이 도는 어둠 */
--vigil:   #17131F;   /* 표면 — 카드·시트 */
--vigil-2: #221C2E;   /* 표면 강조 — 선택된 것 */
--wax:     #E8D6A8;   /* 주 강조 — 촛불. 지금 일어나는 일 */
--marian:  #9C8CC9;   /* 부 강조 — 성모 보라. 신비·단계 */
--linen:   #F2EEE6;   /* 본문 글자 — 제대포의 흰색 */
--dusk:    #8A8296;   /* 보조 글자 */
--ash:     #57516A;   /* 비활성 */
--line:    rgba(242,238,230,.10);
```

**쓰지 않기로 한 색.** 빨강(오류·경고에도 쓰지 않는다 — 기도에서 붉은 경고는 벌주는 인상을 준다. 대신 촛불색으로 주의를 표시한다), 초록(성공 표시로 쓰지 않는다 — 완주는 성취가 아니라 마침이다), 파랑·청록(이 세계의 색이 아니다).

## 3. 타이포그래피 — 두 얼굴을 쓴다

**기도문과 조작 버튼은 다른 성질의 글이다.** 같은 서체로 쓰면 기도문이 앱 UI처럼 읽힌다.

| 역할 | 서체 | 어디에 |
|---|---|---|
| **기도문** | `Noto Serif KR` (400/600) | 성모송·주님의 기도·신비 선포. 세리프는 전례서의 활자다 |
| **조작·표시** | `Noto Sans KR` (400/500/700) | 버튼·라벨·상태 |

**크기 계단** — 시니어(퍼소나 B)가 기준이다. 본문 최소 16px, 기도문은 훨씬 크게.

| 이름 | 크기 / 행간 | 어디에 |
|---|---|---|
| `prayer-lg` | 26px / 1.7 | 앱이 읽는 앞 절 |
| `prayer-md` | 21px / 1.7 | 사용자가 받을 뒷 절 |
| `title` | 20px / 1.4 | 오늘의 신비 |
| `body` | 16px / 1.6 | 기본 |
| `label` | 13px / 1.5 | 버튼·지향 이름 |
| `caption` | 11.5px / 1.5 | 보조 설명 |

시스템 글자 크기 확대(iOS Dynamic Type)를 따른다. 웹에서는 `rem` 기준.

## 4. 시그니처 — 알이 숨을 쉰다

**이 앱에서 화면이 전달해야 하는 것은 딱 두 가지다 — 지금 내 차례인가, 어디쯤인가.** 대부분의 묵주 앱은 그것을 작은 점 열 개와 글자로 알린다. 우리는 **화면 한가운데의 큰 원 하나**로 알린다.

| 상태 | 알이 하는 일 |
|---|---|
| 앱이 앞 절을 읽는 중 | 원의 테두리가 시계 방향으로 차오른다. 안은 어둡다 |
| **내가 받을 차례** | 원이 **숨을 쉰다** — 4초 주기로 촛불색이 밝아졌다 어두워진다 |
| 침묵 진행 | 원은 그대로 있고 진동에 맞춰 한 번 반짝인다 |
| 단이 바뀔 때 | 원이 한 번 크게 확장했다 돌아온다 |

이 하나가 세 가지를 동시에 푼다. **첫째,** "받아 바치세요" 같은 글자가 필요 없다 — 글자를 읽으려면 화면을 봐야 하지만 밝기 변화는 곁눈질로도 안다. **둘째,** 시니어도 보인다 — 화면의 60%다. **셋째,** 눈을 감고 있어도 눈꺼풀 너머 밝기로 차례를 느낀다. 잠자기 전 사용이 주 맥락이므로 이것이 실제로 작동한다.

**대담함은 여기 한 곳에만 쓴다.** 나머지 화면은 전부 조용하게 둔다.

## 5. 컴포넌트와 상태

| 컴포넌트 | 상태들 |
|---|---|
| 큰 버튼 | 기본 · 눌림 · 비활성 · 로딩 |
| 지향 카드 | 선택 안 됨 · 선택됨 · 진행 있음 · 진행 없음 |
| 이어가기 카드 | **없음이 기본**, 있을 때만 나타난다 |
| 알 (시그니처) | 대기 · 읽는 중 · 내 차례 · 침묵 · 단 전환 |
| 알 열 개 | 지난 알 · 지금 알 · 남은 알 |
| 시트 | 닫힘 · 열림 |
| 빈 상태 | 지향이 없을 때 · 진행이 없을 때 |

**빈 상태는 방향을 주는 자리다.** "아직 없습니다"로 끝내지 않고 다음에 무엇을 하면 되는지 적는다.

## 6. 모션

| 무엇 | 시간 | 곡선 |
|---|---|---|
| 화면 전환 | 500ms | `cubic-bezier(.4,0,.2,1)` |
| 알의 호흡 | 4000ms 주기 | `ease-in-out` 왕복 |
| 글자 교체 | 450ms | `ease` |
| 눌림 반응 | 150ms | `ease-out` |

02단계 조사가 확인한 값이다 — 명상 앱은 일반 앱(250~300ms)보다 느린 400~600ms를 쓰고, 그 느림 자체가 진정 효과를 낸다. **`prefers-reduced-motion`을 켠 사용자에게는 호흡을 멈추고 밝기만 바꾼다.**

## 7. 접근성 — 협상 대상이 아닌 것

| 항목 | 기준 | 왜 |
|---|---|---|
| 터치 영역 | 최소 **80px** | 02단계 — 졸음 상태의 부정확한 손가락 |
| 본문 대비 | 4.5:1 이상 | 어두운 화면에서도 읽혀야 한다 |
| 큰 글자 대비 | 3:1 이상 | |
| 시스템 글자 확대 | 200%까지 깨지지 않는다 | 퍼소나 B 시니어 |
| 색만으로 상태를 알리지 않는다 | 밝기·크기·진동을 함께 쓴다 | |

## 8. 톤 — 쓰지 않는 말

06단계 서비스 설계에서 이미 정한 것을 디자인 규칙으로 못 박는다.

| 쓰지 않는다 | 대신 |
|---|---|
| 실패 · 놓침 · 연속 기록이 끊겼습니다 | 이어서 바치기 · 그 자리부터 |
| 축하합니다 · 달성 | 다 바쳤습니다 |
| 붉은 경고색 | 촛불색으로 주의를 표시 |
| 순위 · 비교 · 퍼센트 배지 | 바친 횟수만 조용히 |

## 9. 수용 기준 — 목업이 통과해야 하는 것

07-b 목업은 아래를 전부 만족해야 07-d로 넘어간다.

1. 위 색·서체·크기 계단을 그대로 썼다 (임의의 값이 없다)
2. 알의 다섯 상태가 전부 그려져 있다
3. 빈 상태 두 개가 그려져 있다
4. 터치 영역 80px, 본문 대비 4.5:1을 실측으로 만족한다
5. **Marcello와 나란히 놓았을 때 더 세련돼 보인다** — 이 판정은 공방장이 한다
