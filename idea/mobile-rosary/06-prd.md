# 제품 요구사항 (PRD) — mobile-rosary V1

> 한 줄 요지: **05단계는 "무엇을 첫 판에 넣을까"까지만 정했다. 이 문서는 그것을 "만들 수 있는 것"으로 바꾼다** — 기능마다 규칙과 예외를 못 박고, 같은 일을 경쟁자가 어떻게 푸는지 화면 단위로 대조해 **우리 차이가 진짜 USP인지 판정**한다.

06단계는 세 산출물로 이뤄진다. 이 문서가 첫째다.

| | 산출물 | 무엇을 정하나 |
|---|---|---|
| **06-a** | **이 문서 (PRD)** | 기능 요구사항 · 기능 단위 경쟁 대조 · USP 확정 · 비기능 요구사항 · 데이터 · 엣지 케이스 · 범위 밖 |
| 06-b | [`06-design-system.md`](./06-design-system.md) | 색·서체·컴포넌트·모션·접근성·톤 |
| 06-c | [`06-service-design.md`](./06-service-design.md) | 유저 스토리(걸킨) · 정보 구조 · 백 오피스 판단 |

**왜 이 문서가 새로 생겼나.** 2026-08-28까지 이 파이프라인에는 "화면 수준의 경쟁 분석"이 없었다. 03단계가 시장 수준 경쟁 분석(회사 규모·가격·포지셔닝)을 하고 끝났고, 그다음은 곧바로 만들기였다. 그 결과 USP가 **"한국어 + 손 없이"라는 슬로건**으로만 존재하고 **화면 어디에서 그것이 드러나는지**가 정해지지 않았다. 슬로건은 앱스토어 소개문에는 쓸 수 있지만 개발자에게 넘길 수는 없다.

---

## 1. 이 제품이 파는 것 — 한 문장

> **묵주와 기도문 없이, 화면을 보지 않고, 끊겨도 그날 안에 5단을 마칠 수 있는 한국어 묵주기도 앱.**

05단계 방향성 문장의 압축이며, 아래 모든 요구사항은 이 문장을 더 잘 되게 하는지로 평가한다. 이 문장을 더 낫게 하지 않는 기능 제안은 V1에서 뺀다.

---

## 2. 기능 단위 경쟁 대조 — USP는 여기서 만들어진다

**규칙 하나를 먼저 못 박는다. 다른 것이 전부 USP는 아니다.** 사용자가 **그 차이 때문에 우리를 고를 때만** USP다. 그렇지 않은 차이는 그냥 취향이거나, 더 나쁘게는 남들이 안 하는 데 이유가 있는 것이다. 그래서 마지막 두 칸이 이 표의 핵심이다.

근거는 03단계 피처 매트릭스(7 경쟁자 × 19 피처)와 02단계 조사다. **직접 써 보지 못해 모르는 것은 "미확인"으로 적는다** — 추측을 사실처럼 적지 않는다.

### 2-1. 기도를 시작하는 방법

| | 어떻게 하나 |
|---|---|
| Hallow | 앱을 열고 콘텐츠 목록에서 묵주기도를 고른 뒤 재생. 통합 패키지라 묵주기도까지 여러 단계 |
| Marcello | 앱을 열면 묵주 화면. 단순하다 (이것이 Marcello의 1등 가치) |
| 한국 앱 (성모님·굿뉴스) | 앱을 열고 메뉴에서 고른다. UX 투박 (03 실측) |
| **우리 V1** | 앱을 열면 **시작 단추 하나.** 이어가기가 있으면 그 위에 카드 하나 |
| **차이** | Marcello와 거의 같다. Hallow보다 짧다 |
| **USP인가** | **아니다.** ① 한마디로 시작(음성)이 0표를 받은 것이 이를 뒷받침한다 — 01단계 다섯 마찰 어디에도 "시작이 번거롭다"가 없다. **여기서 이기려 하지 않는다. 지지 않기만 하면 된다.** |

### 2-2. 알을 넘기는 방법

| | 어떻게 하나 |
|---|---|
| Hallow | 음성 가이드가 읽어 주고 자동 진행. 화면을 보지 않아도 되나 **영어** |
| Marcello | 화면의 묵주 알을 **손으로 탭**해 넘긴다 |
| 한국 앱 | 화면 탭 또는 음원 재생. hands-free 아님 (03 피처 매트릭스: 전부 ○) |
| Pocket Rosary | 오디오 가이드 + 햅틱. **8개 언어, 한국어 미확인** |
| Wrist Rosary | Apple Watch 전용. 알마다 햅틱 |
| **우리 V1** | **소리 또는 진동으로 자동 진행.** 휴대폰이 주머니에 있어도 된다 |
| **차이** | 한국어로 이것을 하는 앱이 없다 (03 피처 매트릭스에서 "AirPods hands-free" 행이 전부 ○ 또는 ◐) |
| **USP인가** | **그렇다 — 1순위 USP.** 01단계 다섯 마찰 중 셋(도구 부재·화면 노출 의식·졸음)이 여기서 풀린다. 다만 **한국어라는 조건이 붙어야 USP다.** 영어권에는 이미 있다(Hallow·Pocket Rosary) |

### 2-3. 누가 기도문을 읽나 — 가장 큰 차이

| | 어떻게 하나 |
|---|---|
| Hallow | **앱이 전부 읽는다.** 셀럽 목소리가 강점. 사용자는 듣는다 |
| Marcello | 읽어 주지 않는다. 사용자가 전부 바친다 |
| 한국 앱 | 신비 음원 제공. 전부 읽어 주는 방식 (03: 성모님·굿뉴스 ◐) |
| **우리 V1** | **교대 낭송 — 앱이 앞 절, 사용자가 뒷 절.** 전례의 응답 구조 |
| **차이** | **조사한 어느 앱도 이렇게 하지 않는다.** 전부 "다 읽어 준다" 또는 "안 읽어 준다" 둘 중 하나다 |
| **USP인가** | **그렇다 — 2순위이자 가장 방어하기 쉬운 USP.** 이유가 셋이다. **첫째,** 01단계의 "잡생각으로 집중이 깨진다"를 정면으로 겨냥한다 — 듣기만 하면 딴생각이 들어오지만 받아야 하면 그럴 틈이 준다. **둘째,** 이것은 기능이 아니라 **기도의 방식**이라 베끼기 어렵다. 전례를 이해해야 나오는 설계다. **셋째,** 공방장 닷 보팅 최다 득표(2표)다 |

**여기가 이 제품의 진짜 자리다.** 2-2(hands-free)는 한국어 시장이 비어 있어서 우리 것이지만, 영어권 앱이 한국어를 붙이면 사라진다. 반면 2-3(교대 낭송)은 **경쟁자가 한국어를 붙여도 남는 차이**다.

### 2-4. 끊겼을 때

| | 어떻게 하나 |
|---|---|
| Hallow | 오디오 플레이어 관행상 재생 위치 복원. **묵주기도 문맥의 재개는 미확인** |
| Marcello | 미확인 (단순함이 강점이므로 있을 가능성 낮음) |
| 한국 앱 | 54일·100일 **날 단위** 기록은 있으나(03: ●), **한 번의 기도 안에서 끊긴 자리**는 미확인 |
| 학습·습관 앱 일반 | 연속 기록이 끊기면 **표시로 벌준다** |
| **우리 V1** | 알마다 자리를 저장하고, 그날 안에서도 이어 준다. **끊긴 것을 벌주는 표현을 쓰지 않는다** |
| **차이** | 기능 자체보다 **태도**가 다르다. 재개를 편의가 아니라 **완주율을 지키는 장치**로 본다 |
| **USP인가** | **조건부로 그렇다.** 2026-08-28 관찰이 근거다 — 통증은 끊김이 아니라 "한 번에 해야 한다"는 규범 때문에 재개하지 못해 그날을 잃는 것이다. **다만 이것은 화면에서 눈에 띄지 않는 종류의 USP다.** 써 본 사람만 안다. 그래서 앱스토어 소개문의 첫 줄이 될 수는 없고, **재방문율로 드러난다** |

### 2-5. 여러 지향

| | 어떻게 하나 |
|---|---|
| Hallow | 다중 지향 동시 관리 **없음** (03 피처 매트릭스: ○) |
| 한국 앱 | 지향 입력은 있으나 **동시 관리는 약함** (03: ◐) |
| **우리 V1** | 지향마다 진행 자리를 따로 기억한다 |
| **차이** | 03이 이미 "모든 앱이 약한 자리"로 지목했다 |
| **USP인가** | **아직 아니다.** 닷 보팅 0표였고, 01단계에서도 "구글 캘린더에 따로 적는다"는 우회가 있을 뿐 강한 통증이 아니었다. **④′와 묶였을 때만 의미가 생긴다.** V1에 넣되 앞세우지 않는다 |

### 2-6. 값을 받는 방법

| | 어떻게 하나 |
|---|---|
| Hallow | 월 $9.99 / 년 $69.99 / 가족 $119.99 / 학생 $2.50 / 본당 별도 — **모든 구간을 이미 덮었다** |
| 한국 앱 3종 | 전부 무료 (03 실측) |
| Marcello | 무료·광고 없음 |
| **우리 V1** | 창립 멤버 평생권 9~19달러 **1회.** 매년 걷지 않는다 |
| **차이** | Hallow가 안 쓰는 유일한 형태가 **평생 1회 결제**다 |
| **USP인가** | **거부감을 피하는 장치이지 USP는 아니다.** 값 받는 방식 때문에 앱을 고르는 사람은 없다. 다만 **틀리면 죽는다** — 03이 적은 "한국 무료 default" 위험이 여기 걸려 있고, 그래서 마켓 핏 지표를 따로 둔다 |

### 2-7. USP 확정 — 이 표의 결론

| 순위 | USP | 얼마나 방어되나 | 어디서 드러나나 |
|---|---|---|---|
| **1** | 한국어로 손 없이 5단 완주 | **중간** — 영어권 앱이 한국어를 붙이면 좁아진다 | 첫 사용 30초 안에. 앱스토어 첫 줄 |
| **2** | 교대 낭송 (앱이 앞 절, 내가 뒷 절) | **높음** — 전례를 이해해야 나오는 설계 | 첫 성모송에서 바로 |
| **3** | 끊겨도 그날 안에 이어짐 | 중간 | 두 번째 사용부터. **재방문율로 드러난다** |
| — | 평생 1회 결제 | 낮음 (베끼기 쉽다) | 결제 화면 |

**화면 설계에 주는 지시.** USP 1과 2는 **처음 30초 안에 겪게** 만든다. USP 3은 **겪을 때까지 설명하지 않는다** — 끊기기 전에 "끊겨도 됩니다"라고 알리면 오히려 끊기라고 권하는 인상이 된다.

## 3. 기능 요구사항

각 요구사항에 `FR-##` 번호를 붙인다. 07 목업과 08 테스트 케이스가 이 번호를 참조한다.

### 3-1. 홈

| # | 요구사항 |
|---|---|
| FR-01 | 앱을 열면 오늘의 신비를 요일에 따라 자동으로 정한다 (월·토 환희 / 화·금 고통 / 수·일 영광 / 목 빛) |
| FR-02 | 저장된 진행이 있으면 **시작 단추보다 위에** 이어가기 카드를 둔다. 없으면 카드 자체가 없다 |
| FR-03 | 이어가기 카드는 어디서 멈췄는지(제N단 M번째 알)와 언제 멈췄는지(방금·N분 전·어제)를 적는다 |
| FR-04 | 지향을 고를 수 있고, 고른 지향의 진행이 이어가기 카드에 반영된다 |
| FR-05 | 지향을 추가할 수 있다. 최대 길이 24자 |
| FR-06 | 침묵 진행을 켜고 끌 수 있으며, 상태가 다음 실행까지 유지된다 |
| FR-07 | 받는 사이를 느리게·보통·빠르게 셋 중에서 고를 수 있고 유지된다 |

### 3-2. 기도 진행

| # | 요구사항 |
|---|---|
| FR-10 | 71단계 전체를 순서대로 진행한다 (시작 기도 6 + 5단 × 13) |
| FR-11 | 소리가 켜져 있으면 앱이 **앞 절만** 읽는다. 뒷 절은 읽지 않는다 |
| FR-12 | 앞 절을 마치면 **받는 사이**만큼 기다린 뒤 자동으로 다음으로 넘어간다 |
| FR-13 | 받는 사이 = (900ms + 뒷 절 글자수 × 132ms) ÷ 속도계수. 소리가 없으면 앞 절 몫을 더한다 |
| FR-14 | 침묵 진행이면 소리를 내지 않고 진동만 쓴다 — 알마다 1회, 단 전환 시 3회 |
| FR-15 | 화면 중앙의 알이 상태를 나타낸다 (읽는 중 / 내 차례 / 침묵 / 단 전환). [디자인 시스템 §4](./06-design-system.md) |
| FR-16 | 지금 몇 번째 알인지, 몇 단째인지를 화면에서 볼 수 있다 |
| FR-17 | **알을 넘길 때마다** 진행 자리를 저장한다 |
| FR-18 | 잠시 멈춤 = 자리를 남기고 홈으로. 여기서 끝내기 = 자리를 지우고 홈으로 |
| FR-19 | 5단을 마치면 완주 화면을 보이고 저장된 자리를 지운다 |
| FR-20 | 기도 중에는 화면이 꺼지지 않게 한다 (지원 기기에 한함) |

### 3-3. 오류·예외 (책 5-3 Error Cases 서식)

| 상황 | 앱이 하는 일 | 사용자에게 보이는 말 |
|---|---|---|
| 한국어 음성이 기기에 없다 | 소리 없이 진행하고, 받는 사이에 앞 절 몫을 더한다 | "이 기기에 한국어 음성이 없어 소리 없이 진행됩니다. 진동과 사이는 그대로 동작합니다." |
| 진동을 지원하지 않는다 | 사이만으로 진행한다. 오류를 내지 않는다 | (알리지 않는다 — 조작에 영향이 없다) |
| 기도 중 전화가 온다 | 자리를 저장하고 멈춘다 | (복귀 시 홈의 이어가기 카드로) |
| 저장 공간을 쓸 수 없다 | 진행은 정상, 자리 저장만 실패 | "이 기기에서는 진행 자리를 기억할 수 없습니다." — 한 번만 |
| 지향 이름이 비었다 | 추가하지 않고 시트를 닫는다 | (알리지 않는다) |
| 저장된 자리가 손상됐다 | 자리를 버리고 처음부터로 둔다 | "이어갈 자리를 찾지 못해 처음부터 시작합니다." |

**붉은 경고색을 쓰지 않는다.** 기도 맥락에서 붉은 경고는 벌주는 인상을 준다 ([디자인 시스템 §2](./06-design-system.md)).

## 4. 비기능 요구사항

| 항목 | 기준 | 왜 |
|---|---|---|
| **오프라인** | 인터넷 없이 전부 동작한다 | 지하철·성당은 신호가 약하다. 서버가 없으므로 자연히 충족된다 |
| **개인정보** | 기기 밖으로 나가는 데이터가 **없다.** 계정·로그인 없음 | 지향에는 아픈 사람의 이름이 들어간다. 이것이 서버를 두지 않는 진짜 이유다 |
| **배터리** | 화면 꺼짐 방지를 쓰되 기도 종료 시 즉시 해제 | 잠자기 전 사용이 주 맥락이다 |
| **접근성** | [디자인 시스템 §7](./06-design-system.md) — 터치 80px, 대비 4.5:1, 글자 200% 확대 | 퍼소나 B 시니어 |
| **플랫폼** | V1 = iOS. Android는 V1.5에서 판단 | 02단계 — 한국 iOS 30~35%이나 공방장이 검증할 수 있는 쪽 |
| **성능** | 알 전환 지연 100ms 이내 | 기도의 호흡이 끊기면 안 된다 |

## 5. 저장하는 것

서버가 없으므로 전부 기기 안이다.

```
설정          침묵진행(참/거짓) · 받는사이속도(0.75|1|1.35)
지향[]        아이디 · 이름(24자) · 진행
진행          단계번호 · 단 · 알 · 멈춘시각 · 이어감횟수
```

**저장하지 않는 것**: 사용자 식별자, 위치, 기기 정보, 기도 내용, 통계 전송. 08단계 검증에서 완주율을 재려면 사용자가 **직접 알려 주는 방식**을 쓴다 — 앱이 몰래 세지 않는다.
